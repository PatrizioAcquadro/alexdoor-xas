**Episode:** complete task execution attempt (here it's ACT-A3-N50) / complete sequence of all ticks
	1) Isaac Sim resets robot + door
	2) Choose initial condition
	3) Policy produces the actions
	4) Robot tries to open the door
	5) End of episode: success / timeout / refusal / invalid
	- It contains: 
		- the initial metadata
		- all the data produced during the trial (once it is over), for each tick
		- outcome results
	- The same episode is exported as A2 and A3, with the same id
		- So same physical experience, but represented in a different frame (A2: world frame, A3: door frame)
	- On the disk, each episode is represented by 2 files (for A1, A2, A3)
		- *hdf5:* contains the complete numerical sequences
			- We can think of it as a big table, w/ one row for each tick, and cols = tick id, time, robot state, door state, contact, force, action (A1/A2/A3)
			- N.B. however the cols/groups of cols are stored separately 
		- *meta.json:* for simple H readability; composed of 2 blocks
			- meta: describe w/ what the episode has been produced (what task, robot, scene, action space, policy, seed, simulator-control frequency)
			- outcome: describe how the attempt has ended (success/failure, final door's angle, failure cause, #ticks recorded)
	- We find them in /datasets/door_push_alex_v2/ => produced by the scripted policy, and used to train the models
		- So the 219.95N case does not belong here (since it's produced later by the ACT policy) = this is **evaluation rollout**

**Rollout:** complete execution of a policy in the environment = complete policy process 
- So the difference b/w episode and this is that the rollout is generated by the learned policy, while the episode from the scripted policy

**Control:** process to decide which movement to execute with the robot
	1) Observe robot-door
	2) Policy decides the next movement
	3) Adapter checks-convert that movement
	4) That command is sent to the simulator
	5) The robot & door change state
- Called **feedback control:** since next command is produced by considering the previous command output
	- We observe the state again, and we repeat the 5 steps 

**Tick:** single control cycle iteration = temporal index
- One every 60hz = a tick every for 1/60 ms = 16.67 ms
- In each tick we record: 
	1) Observation of actual state
	2) Policy proposes a movement
	3) Adapter checks (+ modify, if needed) the command/movement
	4) Simulator executes the movement
	5) **Read the new state - contact - force**

**Control period:** time b/w 2 ticks

**Peak:** max force value recorded in a signal (force during the rollout)
- Obtained by taking the max among the magnitudes of the F vector (x,y,z) = single number in N

**Perturbation:** small-controlled numerical modification applied to the original condition

### Seeds Types
**Dataset-generation seed:** generates a dataset demonstration
**Training seed:** used when we construct - train the model => get the checkpoint
- It's just one now (0)
**Rollout seed:** used when we evaluate the checkpoint (trained model)
- The protocol used a series of them
- The same one is used to compare diff policies in the same initial conditions = matched comparison
**Selection/bootstrap seed:** for reproducible selection and statistical computations
